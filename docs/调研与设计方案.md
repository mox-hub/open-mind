# open-mind 思维导图桌面工具 — 调研与设计方案

> 版本：v1.1（2026-10-25）
> 状态：已敲定，作为后续开发基线
> 平台：Windows 10+ / macOS 12+
>
> **v1.1 变更**：确立「完全免费开源、无账号、无商业变现」为产品前提；AI 功能移出路线图（远期社区可选）；新增 §4.5 手感打磨验收清单，手感成为 M1-M3 贯穿的验收标准；分发与许可证策略按零预算开源项目调整。

---

## 1. 调研结论摘要（TL;DR）

1. **市场有空档**：XMind 全面转向订阅制（国内 ¥380/2 年起，AI/高级功能锁在付费档），MindNode 只有 Mac 版，国内免费工具（知犀、幕布、MindLine）要么靠云端账号、要么有节点数限制（幕布免费版 300 节点）。「**跨 Win+Mac、本地优先、无账号、格式开放、完全免费开源**」的桌面思维导图产品目前是空白。
2. **产品前提（已定死）**：不做账户、不做云服务端、不考虑商业变现。纯社区开源项目，比照 Freeplane 的定位、Obsidian 的体验。
3. **第一版唯一优先级：思维导图核心功能 + 使用手感**。手感不是 polish 阶段的甜点，而是产品本身——输入延迟、键盘流、中文输入法（IME）、拖拽反馈、动画节奏，全部进验收清单（§4.5）。
4. **技术栈敲定：Tauri 2 + Vue 3 + TypeScript**。Tauri 2 安装包 ~5MB、内存约为 Electron 的 1/3~1/5，对本地工具类桌面应用是当前最优解；思维导图 UI 以 SVG + CSS 为主，双 WebView（Win: WebView2 / mac: WKWebView）差异可控。
5. **编辑内核敲定：MVP 阶段复用 simple-mind-map（MIT，12.9k stars）快速起步，架构上用适配层隔离**，把省下的工期全部投给手感打磨；产品验证后再评估替换为自研内核（触发条件见 §5.3）。
6. **文件格式敲定：单文件 JSON（`.omd`）**，带 schema version，纯本地存储 + 自动保存 + 崩溃恢复；导入 Markdown / OPML / FreeMind / XMind，导出 PNG / SVG / PDF / Markdown / OPML / FreeMind。
7. **许可证敲定：GPL-3.0**（§8），防止闭源套壳商用，与「纯免费开源」定位一致。

## 2. 市场与竞品分析

### 2.1 竞品矩阵（2026-10）

| 产品 | 平台 | 模式 | 免费版限制 | 核心特色 | 对我们的启示 |
|---|---|---|---|---|---|
| **XMind (2026)** | Win/Mac/Web/移动 | 订阅（国内 ¥380/2年） | 节点数/高级结构/导出受限 | 结构最全、演算模式、AI 生成 | 功能标杆；**订阅制与云端化是被吐槽最多的点** |
| **MindNode** | 仅 Mac/iOS | 订阅 + Setapp | 基础免费 | 苹果生态体验最佳 | 不覆盖 Windows，无直接竞争 |
| **知犀思维导图** | 全平台 | 免费 + 会员 | 节点不限 | AI 生成、模板多 | 国内免费标杆，但**依赖云端账号** |
| **幕布** | 全平台 | 订阅 | **300 节点上限** | 大纲笔记一键转导图 | 大纲↔导图双视图是刚需，必须做 |
| **MindLine** | 全平台 | 免费+内购 | 基础免费 | 极简 | 证明「简洁免费」有市场 |
| **Freeplane (开源)** | Win/Mac/Linux | 免费开源 (GPL) | 无 | 功能强但 UI 陈旧 | 开源完全可行；**体验和手感才是胜负手** |
| **Miro / MindMeister / Whimsical** | Web 为主 | 订阅 | 节点/图数限制 | 实时协作 | 协作是云端优势，**我们不碰** |

### 2.2 用户痛点（= 我们的机会）

1. **订阅疲劳**：XMind 从买断转订阅引发老用户不满，大量用户搜索「如何取消自动续费」；产品分析普遍指出「免费版够用、付费意愿低」。
2. **数据主权**：`.xmind` 是封闭 zip 包，多数工具导出只给图片/PDF，可编辑格式（OPML / FreeMind `.mm`）才是可靠交换格式——用户被锁死。
3. **离线被忽视**：主流产品重心转向云端协作，纯本地离线、文件在手的老用户体验停滞。
4. **免费版限制**：节点数上限（幕布 300）、导出水印、高级结构（鱼骨图/时间轴）付费。

### 2.3 2026 趋势（仅作参考，不追）

- AI 生成导图成为商业产品标配（Xmind AI、MindMap AI、Miro AI 等）——**明确不跟**：AI 依赖外部服务与持续成本，与「无账号、无变现、纯本地」前提冲突。
- 本地优先（local-first）理念在笔记工具（Obsidian、Logseq）已验证成功，思维导图品类尚无同等定位产品。

**结论：定位「思维导图领域的 Obsidian」——本地文件、开放格式、完全免费开源，把商业产品不认真做的「基础体验」做到极致。**

## 3. 产品定位（敲定）

### 3.1 一句话定位

> 本地优先、完全免费开源的跨 Windows/macOS 思维导图桌面工具：文件在你手里，格式开放可迁移，无账号、无遥测、无订阅——只有一个打磨到极致的编辑器。

### 3.2 目标用户

- **主力**：被订阅制劝退的 XMind 免费版用户、学生、知识工作者、写作者；
- **次级**：已有 Obsidian/坚果云等本地工作流、希望导图文件纳入自有同步体系的用户。

### 3.3 差异化（按重要性排序）

1. 完整功能**离线可用**，无登录、无账号、无遥测；
2. **开放单文件格式** + 全量可编辑格式导入导出（进来容易、离开自由）；
3. **手感**：键盘流全流程操作、中文输入法友好、亚帧级响应（§4.5 是硬验收）；
4. 大纲 ↔ 导图**同源双视图**，输入效率对标幕布；
5. 轻量：安装包 <15MB，冷启动 <1.5s；
6. 真正开源（GPL-3.0）：社区可自查、可贡献、可续命。

### 3.4 非目标（明确不做）

- **账号体系（永远不做）**、云服务端、商业变现、付费档、广告、遥测；
- Web 版、移动端、多人实时协作、团队管理后台；
- **AI 功能**：近期路线图不做（远期若社区想做，架构已预留命令层，见 §5.6）；
- 任何依赖联网才可用的功能。

## 4. 核心功能（敲定）

### 4.1 P0 — MVP（必须有，缺一不可上线）

**编辑核心（效率与手感是思维导图产品的全部）**
- 节点操作：新增子节点 `Tab`、新增同级 `Enter`、删除 `Del`、编辑 `F2`/双击；
- 多选（`Ctrl/Shift+点击`、橡皮筋框选）、批量删除/样式；
- 拖拽：换父、排序、跨子树移动（含子树整体移动），**拖拽中有清晰的落点指示**；
- 折叠/展开（单节点 + 递归）；
- 撤销/重做（`Ctrl+Z` / `Ctrl+Shift+Z`，≥100 步，**撤销后焦点与视口回到操作前状态**）；
- 剪贴板：子树复制/粘贴；**多行纯文本粘贴自动生成子树**（从网页/文档复制大纲直接成图）；
- 键盘导航：方向键在节点间移动、`Home` 回根节点、画布跟随焦点；
- **中文输入法（IME）正确处理**：组合输入中不误触快捷键、不丢字、不闪烁、候选框定位正确。

**视图**
- 结构：思维导图（双侧）、逻辑图（右侧）、组织架构图，共 3 种；
- 缩放（`Ctrl+滚轮`以鼠标为锚点 / 触控板捏合）、平移（空格拖拽/触控板双指）、适应画布、居中当前节点，**带平滑过渡动画**；
- 小地图（minimap）导航，视口矩形可拖动；
- **大纲视图 ↔ 导图视图**同源切换（大纲视图支持直接编辑与拖拽缩进）。

**样式与标注**
- 内置主题 ≥8 个（含明暗），支持节点级覆盖：文字色、背景色、形状（圆角矩形/椭圆/矩形）；
- 关联线（任意两节点连线 + 文字）、外框（框选分组 + 备注）、概要节点（括号汇总）；
- 标注：优先级 1-5、进度、emoji 图标、备注（支持 Markdown）、超链接。

**文件与数据**
- 新建/打开/保存/另存为、最近文件、启动恢复上次会话（含折叠状态与视口位置）；
- **自动保存**（变更后 500ms 防抖写盘，原子写，不阻塞输入）+ 崩溃恢复（写前临时副本）；
- 导入：Markdown、OPML、FreeMind `.mm`；
- 导出：PNG（1x/2x）、SVG、PDF、Markdown、OPML、FreeMind。

**基础体验**
- 明/暗/跟随系统主题；中文/英文界面（i18n 字符串从第一天外置）；
- 文档内查找替换。

### 4.2 P1 — v0.5（上线后 4~6 周内，手感优先排期）

- **手感专项收尾**：§4.5 清单中未在 M1 完成的项全部清零（这是本阶段第一优先级，先于一切新功能）；
- **XMind `.xmind` 导入**（拉新最强钩子，zip 内 content.json 解析，结构无损）；
- 演示模式（按节点层级逐级聚焦播放，类似 XMind 演算）；
- 多标签页、多窗口；
- 本地版本快照（每小时/每日自动快照，可回滚，存于 `.omd-history/`）。

### 4.3 P2 — v1.0 及以后

- 图片节点（拖入图片，内嵌或相对路径两种策略）；
- ZEN 专注模式；
- 鱼骨图、时间轴结构；
- 快捷键自定义；
- 模板库（内置 + 本地导入）；
- 文档加密（口令 + AES，Rust 侧实现）；
- WebDAV/坚果云/iCloud Drive 文件级同步指引与冲突提示（仍是纯文件，无账号）；
- 插件系统；
- Linux 版（Tauri 顺带产出）；
- 实时协作（Yjs/CRDT，远期，仅当社区强烈要求且有人认领）。

### 4.4 功能砍单原则

任何功能若依赖云账号、强制联网或持续服务器成本，一律不进路线图。

### 4.5 手感打磨验收清单（M1–M3 贯穿的硬验收标准）

> 手感是本产品第一优先级。以下每一条都是可测量的验收项，进 CI 基准或人工验收清单，不达标不算完成。

**性能**
- [ ] 按键（Tab/Enter/方向键）到渲染 < 16ms（一帧）；
- [ ] 5000 节点文档：缩放/平移 ≥ 50fps，折叠/展开 < 100ms；
- [ ] 冷启动到可编辑 < 1.5s；自动保存零卡顿（保存不进主线程渲染路径）。

**键盘流**
- [ ] 不碰鼠标可完成：建图 → 输入完整结构 → 调整结构（拖拽除外）→ 折叠 → 导出；
- [ ] Enter 结束编辑后自动选中该节点，Tab/Enter 可立即连续输入（节奏无断裂）；
- [ ] 双击进入编辑时，光标落在点击处的字符，而非全选；
- [ ] 方向键导航跨折叠节点、跨左右分支行为符合直觉（左侧分支反向）。

**中文输入（IME）**
- [ ] 拼音组合输入中：快捷键全部静默、不丢字、不跳焦点；
- [ ] 候选框跟随光标位置（双 WebView 各验一遍：微软拼音、搜狗、macOS 原生）；
- [ ] 组合中撤销/保存等副作用被正确延迟到组合结束。

**交互反馈**
- [ ] 拖拽时实时显示插入位置指示（高亮目标父节点与落点间隙）；
- [ ] 节点增删/移动/折叠有 150–200ms ease 过渡动画，无布局跳变；
- [ ] 缩放以鼠标位置为锚点，触控板捏合与双指平移符合平台习惯；
- [ ] 选中/悬停/编辑态三态视觉清晰，主题切换即时生效。

**稳健性（用户感知层面）**
- [ ] 撤销/重做不丢焦点、不跳视口；
- [ ] 崩溃/强退后重开：内容、折叠状态、滚动位置、上次活动节点全部还原；
- [ ] 外部程序修改文件时提示重载/保留，不静默覆盖；
- [ ] HiDPI（150%/200% 缩放）与多显示器下无模糊、无错位。

## 5. 技术方案（敲定）

### 5.1 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 桌面壳 | **Tauri 2** | 安装包 ~5MB vs Electron ~150MB；内存 1/3~1/5；Rust 侧做文件 IO/自动保存/文件监听很合适；对零预算开源项目，体积与维护成本都是优势。代价：需少量 Rust；双 WebView 渲染差异需测试矩阵覆盖 |
| 前端框架 | **Vue 3 + TypeScript + Pinia + Vite** | simple-mind-map 官方示例是 Vue 系，社区中文资料多；Pinia 管文档树与 UI 状态 |
| 编辑内核 | **simple-mind-map（MIT）起步** | 见 §5.3 |
| 渲染 | SVG | 思维导图节点量级（数千）SVG 足够，且导出 SVG/PDF 天然免费、命中测试简单 |

**为何不是 Electron**：本产品定位「轻量本地工具」，Electron 的体积/内存劣势与定位直接冲突；且我们不需要 Node 生态的 native 模块。

**双 WebView 风险对策**：Win（WebView2/Chromium）与 mac（WKWebView/WebKit）差异集中在字体渲染、滚动条、SVG 滤镜、IME 行为；约定只用两者都稳定支持的 CSS/SVG 子集，两端各设一台 CI 截图对比；**IME 行为列入 M0 验证项**。

### 5.2 架构

```
┌──────────────────── Tauri 2 桌面壳 ─────────────────────┐
│  Rust core                                              │
│   · 文件读写 / 自动保存（防抖+原子写：tmp→rename）        │
│   · 崩溃恢复副本 · 文件监听（外部修改提示重载）            │
│   · 版本快照目录管理 · 更新器 · 系统深链 (open-mind://)   │
├──────────────────── WebView 前端 ───────────────────────┤
│  Vue 3 + TS                                             │
│   ├─ EditorAdapter（接口层，见 §5.3）                    │
│   │    └─ 实现 A：simple-mind-map 封装                   │
│   │    └─ 实现 B（未来）：自研 SVG 内核                   │
│   ├─ 大纲视图 / 查找替换 / 命令面板 / 演示模式            │
│   ├─ Pinia：文档树（唯一事实源）+ UI 状态 + 主题          │
│   └─ 导入导出：Markdown/OPML/FreeMind/XMind 解析器(TS)   │
└─────────────────────────────────────────────────────────┘
```

**关键原则：文档树数据的唯一事实源在我方 store**（simple-mind-map 通过适配层同步进出），大纲视图、导入导出、未来的扩展都只操作 store 的树，不直接碰内核内部状态。这是保证内核可替换、功能可并行开发的结构性决策。

**手感相关的两条架构约束**：
1. 内核渲染循环与数据同步解耦——store 变更走批量 patch 同步到内核，避免每次按键全量序列化；
2. 自动保存序列化放在 Web Worker / Rust 侧，主线程只负责渲染与输入，保证 16ms 指标可达。

### 5.3 编辑内核决策：复用起步，保留替换权

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. 复用 simple-mind-map | MIT 可商用/可并入 GPL 项目；功能覆盖 MVP ~80%（多结构/主题/大纲/小地图/导入导出）；MVP 提速 4-6 周，**省下的工期投给手感打磨** | 库本身**低维护**；代码质量一般；深度魔改成本随时间上升 | **MVP 采用**：fork 进自己仓库锁定版本 |
| B. 自研 SVG 内核 | 长期资产；性能/动画/输入法细节完全可控（手感天花板更高）；整洁树布局算法成熟（reingold-tilford / tidy-tree 有大量参考实现） | 启动 3-6 个月，单人不可行 | 产品验证后（>500 周活）再启动 |

**触发替换的条件**（满足任一）：① 手感验收项（§4.5）在 simple-mind-map 上无法达标（尤其 IME、动画、大文档性能）；② 需要实时协作（CRDT 需深度介入数据层）；③ fork 维护成本连续两个月超过自研推进速度。**注意：因手感升为第一优先级，条件①很可能在 v0.5–v1.0 之间触发，M2 起就要持续评估。**

### 5.4 文件格式（敲定：单文件 JSON，扩展名 `.omd`）

```jsonc
{
  "format": "open-mind",
  "version": 1,                    // schema 版本，读取时向上迁移
  "meta": {
    "title": "产品规划",
    "createdAt": "2026-10-25T09:00:00Z",
    "updatedAt": "2026-10-25T17:00:00Z",
    "theme": "classic",
    "structure": "mind-map"        // mind-map | logic-right | org-chart
  },
  "root": {
    "id": "n_1",
    "text": "中心主题",
    "children": [
      { "id": "n_2", "text": "分支", "children": [], 
        "note": "", "markers": ["priority-1"], "link": null,
        "style": { "bg": null, "color": null, "shape": null },
        "collapsed": false }
    ]
  }
}
```

- **为什么不是 Markdown 当主格式**：优先级/外框/关联线/样式在纯文本中无法无损表达；JSON 单文件仍然 git 友好、同步盘友好。
- Markdown 无损往返通过「导出 Markdown（缩进大纲 + frontmatter）」实现，作为交换格式而非主格式。
- 写盘一律**原子写**（写临时文件后 rename），杜绝半截文件。

### 5.5 导入导出矩阵

| | P0 | P1/P2 |
|---|---|---|
| 导入 | Markdown、OPML、FreeMind | **XMind**（P1）、Txt 大纲、Word（docx 大纲级别） |
| 导出 | PNG(1x/2x)、SVG、PDF、Markdown、OPML、FreeMind | Xlsx、HTML（可交互只读图） |

XMind 导入是拉新关键：解析 `.xmind`（zip）内 `content.json`，样式尽力映射，结构无损。

### 5.6 关于 AI（已移出路线图，仅留架构说明）

近期不做任何 AI 功能。架构上唯一的预留：所有编辑操作走**命令模式（command pattern）**统一入口——这本来就是为了撤销/重做和手感测试所需，未来社区若想做 AI（BYOK 直连用户自己的 API Key，无账号），只需新增一类「批量生成命令 + diff 预览确认」，不改数据层。

### 5.7 打包与分发（零预算策略）

- **分发渠道：GitHub Releases**，支持 Tauri updater 自动更新（静态 JSON feed，托管在 GitHub Pages / Release 附件，零服务器成本）；
- **签名（零预算对策）**：
  - Windows：初期**不购买代码签名证书**，README 提供 SmartScreen「仍要运行」指引；若未来获社区赞助再补签；
  - macOS：初期使用 **ad-hoc 签名**（免费），README 说明「右键→打开」绕过 Gatekeeper；Apple Developer（$99/年）视赞助情况决定；
  - 注意：tauri-plugin-updater 的更新包自带 Ed25519 签名校验，与应用签名是两回事，零预算下自动更新依然安全可用；
- 提供 `winget` / `brew install`（Homebrew cask）收录作为中期目标，可显著缓解未签名警告。

## 8. 开源与分发（敲定）

- **许可证：GPL-3.0**。理由：与「完全免费开源、无商业变现」定位一致，防止闭源套壳商用分发；simple-mind-map 为 MIT，可合法并入 GPL 项目（方向兼容）。备选 MIT 更利于传播但放弃了防套壳保护——**敲定 GPL-3.0**。
- **仓库**：GitHub 单仓（monorepo：`src/` 前端 + `src-tauri/` Rust + `docs/`），README 中英双语，CONTRIBUTING、issue/PR 模板、行为准则从第一天齐备。
- **透明承诺**：无账号、无遥测、无联网依赖（除自动更新检查，且可关闭）。
- **社区可选**：GitHub Sponsors / 爱发电链接放 README，纯自愿，永不与功能挂钩。
